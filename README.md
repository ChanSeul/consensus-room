# Consensus Room

**Claude와 Codex가 계획하고, 만들고, 서로 검토하는 과정을 한곳에서 관리하는 개발 작업 도구입니다.**

사람이 AI 사이에서 대화와 자료를 옮겨 주는 수고를 줄이고, **누가 무엇을 근거로 작업했는지** 기록합니다.

## 누가 무엇을 하나요?

![사용자가 목표와 중요한 결정을 맡고, 중재자가 진행을 조율합니다. 플래너는 계획하고 러너는 코드를 바꾸며, 계획 검토자와 코드 검토자가 각각 확인합니다. Claude와 Codex는 역할별로 배정합니다.](docs/images/readme-roles.svg)

## 한 작업은 이렇게 진행돼요

![목표와 자료 확인 → 계획 검토와 승인(계획을 고른 작업만) → 구현 → 검사와 리뷰 → 결과 저장. 티켓 작업은 계획 없이 바로 구현합니다(점선). 수정할 점이 있으면 구현으로 돌아갑니다. 커밋은 확인하고 되돌릴 수 있는 저장 기록이며, 원격 전달은 승인된 범위에서 진행합니다.](docs/images/readme-workflow.svg)

큰 작업은 **결과를 확인할 수 있는 작은 작업**으로 나누고, 지금 할 일부터 구체화합니다. 중재자는 승인된 범위에서 계속 진행하며, 사용자 결정이 필요한 질문은 대화로 돌려줍니다.

계획이 필요 없는 **일반 작업**(ticket)은 바로 구현·리뷰·수정으로 이어집니다. **계획 작업**(planned)은 여러 Markdown 파일로 계획을 작성하고, 리뷰어가 확인한 현재 판을 사용자가 승인한 뒤 구현합니다.

첫 턴에는 과제와 역할 지침을 전달합니다. 이어지는 턴에는 **상대의 응답 원문과 아직 받지 않은 새 사실**을 같은 세션으로 보냅니다. 계획 파일·버전·변경분은 보존하고, 대화의 문맥 압축은 각 Claude·Codex 세션에 맡깁니다.

처음에는 엔진이 계획을 조각내 읽게 하고, 지적 분류·근거 심사·마무리 확인까지 맡았습니다. 실제 앱 작업에서는 이 단계들을 복구하느라 구현이 늦어졌습니다. 현재는 작업자와 중재자가 내용을 판단하고, 엔진은 권한·실행·결과 보존을 맡도록 바꿨습니다. 대체된 계획 제어와 확인 사슬도 제거했습니다.

## 자료가 부족하거나 실행이 끊기면 어떻게 하나요?

- **자료를 읽지 못하면:** 부족한 자료와 그 자료가 필요한 작업을 후속 목록에 남깁니다. 확보한 근거로 할 수 있는 작업을 진행하며, 읽지 못한 자료를 확인했다고 처리하지 않습니다.
- **응답 형식이 맞지 않으면:** 같은 세션에서 한 번 교정합니다. 그래도 유효하지 않으면 받은 원문과 실패를 남깁니다. 세션 유실은 자동으로 새 대화를 열지 않고, 중재자가 역할과 사유를 명시해 교체합니다.
- **자료가 바뀌면:** 바뀐 내용을 작업 세션에 사실로 전달합니다. 영향은 작업자와 중재자가 판단합니다. 원문이 바뀌었다는 이유만으로 승인한 계획이나 진행 중인 작업을 멈추지 않습니다.
- **자동 진행을 승인하면:** 서버가 그 계획의 실행·검토·로컬 완료와 지정된 다음 단계 열기를 이어 갑니다. 다음 단계가 계획을 고른 작업이면 계획까지 시작하고, 티켓 작업이면 열어 두고 구현 시작을 기다립니다. 서버를 재시작해도 기록을 복구하며, 사용자 중지·새 실패·새 계획의 승인 조건을 확인합니다.

엔진 복구만으로 진행할 수 없으면 중재자가 현재 과제·계획·변경 코드·검증 결과·남은 일을 보존해 승인된 다른 실행 경로로 인계합니다. 실패하거나 실행하지 않은 검사를 통과로 처리하지 않습니다.

수집기는 원문과 조회 결과를 기록하고, 근거 관리자는 누락과 재수집 상태를 보존합니다. 작업 엔진은 승인·실행 조건과 결과를 확인하고, 진행 조정기는 허용된 다음 행동을 실행합니다. 각 부분의 책임을 나눠 알림이나 대화 연결만으로 작업 진행이 결정되지 않게 했습니다.

## 실제 화면은 이렇게 읽어요

![위쪽에는 중재자·플래너·계획 검토자·러너·코드 검토자 카드가 있고, 아래쪽 Slack·Jira·Figma 자료에서 참여자의 대화로 연결선이 이어지는 세션 그래프](docs/images/consensus-room-session-graph.png)

- **위쪽 카드:** 작업을 맡은 역할과 현재 상태입니다. 카드를 누르면 대화와 전달 자료를 확인할 수 있습니다.
- **아래쪽 카드:** 연결한 Slack 대화, Jira 업무 문서, Figma 디자인입니다.
- **연결선:** 점선은 역할·자료의 연결 관계, 청록색 실선은 자료 전달 기록입니다. 자료를 전달했다는 기록과 계획·결과의 승인은 구분합니다.

## 어떻게 시작하나요?

연결된 Claude 또는 Codex 대화에서 목표를 전달합니다. 예를 들면:

> “주문 화면 개선을 consensus-room으로 진행해 줘. 먼저 연결한 기획서와 디자인을 확인해 줘.”

목표가 정해지지 않았다면 논의부터 시작할 수 있습니다. **지시는 대화에서, 진행 확인은 웹 화면에서** 합니다. 기본적으로 시간·토큰 사용량을 기록하며, 사용자가 한도를 정하면 그 한도도 적용합니다.
