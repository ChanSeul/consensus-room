# 계획 입력을 제한하고 중간 결과에서 이어가기

계획 작성·개정·감사·종결 검토에 선택적으로 적용하는 서버 제어 조사 방식이다. 구현 모델과 추론 설정은 바꾸지 않는다. 기존 토픽에는 자동 적용하지 않으며, 실사용 검증 전 기본값은 꺼져 있다.

인증된 `POST /api/topics/:id/planning-control`로 실행 중이 아닌 토픽에 적용한다. 기존 멱등성 키와 중재자 권한 검사를 사용한다. `CONSENSUS_ROOM_GUARDED_PLANNING=1`은 **이후 생성하는** 토픽에만 적용한다. 운영 토픽의 예산·리뷰·재작성 한도는 이 설정으로 늘어나거나 초기화되지 않는다. 예산을 소진한 토픽의 실사용 검증은 추가 예산 승인 후 별도로 진행한다.

## 모델이 받는 내용

모델은 필수 지시문과 작업 계약, 짧은 중간 결과, 서버가 허용한 자료 조각을 받는다. 파일·검색·캐시된 외부 근거·메모리·이미지를 읽으려면 `planningStep.requests`로 종류, 선택자, 질문, 바이트 위치를 반환한다. 서버가 Git 스냅샷이나 이미 저장된 외부 근거에서 자료를 가져온다. 진단 원문처럼 엔진이 허용한 작업 트리 밖의 파일도 `artifact` 자료로 등록해 해시를 확인하고 분할 전달한다. 이 경로에서 Slack·Jira·Figma 원문을 다시 수집하지 않는다. 외부 근거의 갱신은 기존 evidence 기능이 담당한다.

| 항목 | 제한 |
| --- | --- |
| 최종 조립 텍스트 입력 | UTF-8 64 KiB |
| 직렬화한 자료 조각 | 8 KiB |
| 한 회차 자료 묶음 | 24 KiB |
| 중간 결과 | 12 KiB |
| 회차별 읽기 요청 | 4개 |
| 조사 / 최종 정리 | 최대 8회 / 추가 1회 |
| 이미지 | 회차당 PNG 1개, 5 MiB 이하 |

텍스트 한도는 CLI 어댑터가 필수 지시문을 붙인 뒤 다시 검사한다. 필수 계약이 넘치면 내용을 잘라 보내지 않고 중간 결과를 남겨 멈춘다. 이미지 바이트는 텍스트와 따로 기록한다. 이 수치는 모델 전체 문맥 한도나 토큰 수를 뜻하지 않는다. CLI 자체 지시문과 공급자 내부 처리는 별도다.

Claude는 첫 계획에서 생성하거나 연결한 세션을 조사·개정·구현·수정까지 이어 쓴다. 승인 계획의 해시·범위·계획 세대와 작성 세션 ID를 함께 저장하고, 첫 구현에서 이 연결을 확인한다. 구현 시작에는 승인 지시와 이후 변경분만 전달하며, 이미 작성한 계획 전문과 전달한 자료 조각을 반복 삽입하지 않는다. 계획 개정에 정확한 행 번호가 필요하거나 문맥 압축으로 세부 내용을 잃었을 때만 저장된 원문을 조회한다. 압축으로 잃은 자료 조각은 `rereadReason`을 명시한 요청으로만 제한 내에서 다시 제공하며 새 근거로 집계하지 않는다. 세션 유실·연결 불일치 시 자동으로 새 세션을 생성하지 않고 중재를 기다린다. 기존 토픽은 이 기능을 켜고 검증된 계획 연결이 생긴 뒤에 적용한다. Codex 검토는 기존 세션을 이어가고 이미 전달한 동일 조각을 다시 싣지 않는다. 누적 호스트 입력·응답 바이트가 제한을 넘거나 기존 세션의 크기를 알 수 없으면 세션을 교체하지 않고 중재를 기다린다.

CLI의 직접 조회 도구도 닫는다. Claude는 빈 tools 목록과 빈 MCP 설정을 사용한다. Codex는 셸, 이미지 읽기, 웹, 앱·브라우저·컴퓨터 도구, 플러그인과 하위 에이전트를 비활성화한다. 필수 프로젝트 지시문은 서버가 넣는다. 이미지 첨부는 서버가 확인한 근거 이미지 한 장만 별도 입력으로 전달한다.

## 중단과 재개

첫 호출 전과 유효 응답마다 SQLite에 중간 결과를 저장한다. 작업 범위, 계획 세대, 단계, Git 트리, 외부 근거, 선택한 메모리, 지시문 해시를 결속한다. 현재 작업 트리의 미커밋 변경도 임시 Git index로 스냅샷에 포함하며 실제 index는 변경하지 않는다.

같은 계획 시도의 모든 조사 호출은 하나의 재작성·리뷰 예약을 공유한다. 재시작과 재시도는 이미 사용한 토큰·시간과 회차 수를 유지한다. 자료가 바뀌면 이전 중간 결과를 보관하고 사실 판단을 무효화한 뒤 새 자료로 확인한다. 같은 범위에 새 사용자 결정·근거가 추가되면 다음 재시도에 입력과 순번을 갱신하고 다시 판단한다. 변경 전에 받은 응답을 그대로 확정하지 않는다. 같은 Claude 세션 ID와 전달한 작업 지시 해시를 보관하며, 서버 재시작 뒤에도 승인 계획과 연결된 세션을 구현에서 재개한다. 요청 수·비용·입력 바이트도 호출별 차이만 합산한다.

실행 또는 전체 예산의 입력·출력·시간 중 하나라도 80%에 도달하면 추가 자료 조회를 멈춘다. 관측한 가장 큰 호출의 125%만큼 여유가 있을 때만 최종 정리를 시도하며, 실제 상한은 기존 예산 원장이 계속 집행한다. 이 여유 계산은 다음 호출 비용을 보장하는 예측값이 아니다.

두 회차 연속 새 근거나 해소된 질문이 없거나, 사용량이 누락되거나, 검토 세션이 너무 크면 중간 결과를 보존하고 멈춘다. 사용량 누락은 재시도로 0으로 취급하지 않는다. 해당 시도의 예산과 세션을 중재자가 확인해야 한다. 원문 응답도 보존하며 형식 오류·남은 질문이 있는 결과는 최종 계획으로 승인하지 않는다. 계약 교정이 서버 제어 조사와 한도를 우회하는 별도 호출로 빠지지 않는다.

## 검증과 지표 해석

공개 워크플로 재시도, 중간 결과 복구, 예산 경계, 자료 변경, UTF-8 조각 재구성, 경로 이탈·인증 파일 배제, 불완전한 계획 차단을 테스트한다. 어댑터 테스트는 최종 입력 크기와 도구 설정, 이미지 전송을 검사한다.

2026-09-23에 설치된 Codex CLI `0.155.0-alpha.9`와 Claude Code `2.1.280`을 임시 홈과 로컬 모의 API에 연결했다. 서버가 받은 요청에서 Codex는 도구 목록이 없었고 Claude는 빈 목록을 보냈다. Claude 이미지 입력도 같은 로컬 경로에서 파싱됐다. 모의 API가 의도적으로 요청을 거절했으며 실제 모델 사용량이나 계획 품질을 측정한 실험은 아니다. CLI 업데이트 뒤에는 이 경계를 다시 확인해야 한다. Claude의 계획→구현 재개 시 모델·ultracode·도구 권한 전환은 어댑터 명령 계약으로 검사하며, 실제 모델의 문맥 보존 품질은 별도 파일럿에서 확인해야 한다.

화면은 누적 입력·캐시 읽기·호스트 텍스트 바이트·관측된 요청별 최대 입력을 구분한다. 요청별 입력을 제공하지 않는 CLI는 `측정값 없음`으로 표시한다. 누적 입력을 한 번의 문맥 크기나 과금액으로 해석하지 않으며, 입력 바이트 감소를 실제 토큰 절감률로 보고하지 않는다. 실사용 파일럿이 끝나기 전에는 기본 적용이나 비용 개선이 검증됐다고 보지 않는다.

Claude의 누적 문맥에는 CLI의 기존 자동 압축 설정을 적용한다(계획 800,000 / 구현 600,000). 이는 호스트 입력 64KiB 제한이나 측정된 요청별 토큰 수와 다른 설정이며, 세션 ID 유지가 모든 대화 원문의 영구 보존을 뜻하지 않는다. Codex 검토의 누적 호스트 입력 제한과 세션 유지 정책은 그대로다.
