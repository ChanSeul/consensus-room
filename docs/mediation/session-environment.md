# 작업 세션 환경

Planner·implementer·reviewer는 대상 프로젝트의 토픽 worktree에서 실행한다(`cwd=topic.worktreePath`). 중재·배포 절차는 호스트가 처리하며 작업 세션에는 배정된 역할·승인 범위·결과 계약과 프로젝트 규칙을 전달한다.

## 지침 선택

- 공통 작업 지식의 정본은 [공통 중재 정책](policy.md)의 `cr-worker-knowledge` 구간이다. 이 구간의 본문은 개인 전역 지침·프로젝트 메모리·스킬이 없어도 일반 작업자 입력에 먼저 포함된다. 개인 경로·계정·상시 권한·프로젝트 전용 값은 이 본문에 넣지 않는다.
- 소스에서 실행할 때는 현재 정본을 읽는다. 독립 실행 번들은 빌드 시 같은 구간을 포함하므로 소스 checkout이 없어도 동작한다. 번들의 지침을 갱신하려면 새 번들을 만들고 해당 설치 절차로 교체한다. 기록한 버전이나 해시는 본문 일치의 근거이며 모델이 읽고 이해했다는 증명은 아니다.
- Claude는 전역·프로젝트 `CLAUDE.md`, Codex는 전역·프로젝트 `AGENTS.md`를 사용한다. Codex의 `AGENTS.override.md`가 있으면 해당 범위의 `AGENTS.md`보다 먼저 쓴다.
- 프로젝트 파일은 worktree에서 읽고, 없으면 원본 저장소에서 읽는다. gitignored 지침을 worktree마다 복사하지 않는다.
- 독립된 `<!-- interactive-session-only: 설명 -->` 줄이 있으면 그 위까지만 작업자에게 전달한다. 표시가 없으면 기존 본문을 유지하며 코드 블록·인라인 예시는 경계로 취급하지 않는다.
- 개인·프로젝트 지침의 크기 검사·비밀 값 가림·필수 입력 해시는 실제 전달할 본문에 적용한다. 공통 정본은 전체 구간을 전달하며 공개 전에 개인 정보와 비밀이 없는지 검토한다. 무시된 파일의 대화형 전용 부분만 바뀌면 계획 입력을 무효화하지 않는다. Git으로 추적하는 파일의 변경은 기존 작업 트리 검사대로 처리한다.
- 대상 프로젝트의 요구사항·근거·구현 제약은 작업자 본문에 둔다. 대화형 세션에서만 필요한 운영 절차는 경계 아래에 둔다. 작업자에게 필요한 규칙을 경계 아래에만 두지 않는다.

## 모델별 전달

Codex의 일반 턴은 작업자 지침을 `developer_instructions`로 받고 stdin으로 배정된 작업을 받는다. Native 프로젝트 문서 발견은 끄므로 대화형 전용 부분이 다시 들어오지 않는다. 입력 바이트 기록에는 지침과 stdin을 모두 포함한다.

Claude의 일반 턴은 기존 stdin 경로를 유지한다. 세션·worktree·전달 본문의 SHA-256을 호스트의 `claude-plugin/instruction-receipts`에 기록한다. 성공적으로 전달한 동일 지침은 다음 턴에 반복하지 않는다. 지침 변경·압축 감지 뒤에는 다시 전달하며 실패·취소·0턴 합성 결과는 새 전달 영수증을 만들지 않는다. 영수증은 서버 재시작 뒤에도 유지한다. 시스템 프롬프트 플래그는 바꾸지 않는다.

계획 왕복의 플래너·리뷰어 턴도 일반 턴과 같은 경로로 지침을 받는다. 격리 host-review에는 프로젝트·전역 지침을 넣지 않는다.

공통 작업 지식도 같은 전달 경로와 영수증에 포함된다. Claude의 성공한 같은 세션에서 본문이 바뀌지 않으면 재전송을 생략하며, 지침 변경과 기존 압축·실패 처리 계약을 따른다. Codex의 일반 create/resume에서는 `developer_instructions`에 포함된다. 판단에 필요한 입력만 받는 protocol-only 턴과 격리 실행에는 공통 본문을 추가하지 않는다.

중재자는 기존 대화 세션이므로 별도 입력 경계를 사용한다. `cr briefing`은 서버가 반환한 현재 정책의 전체 본문과 SHA-256을 출력하고 본문·버전·공통 구간이 없거나 일치하지 않으면 실패한다. 출력물을 연결된 대화에 전달해야 한다. CLI 출력, 실제 세션에 전달, 모델의 준수, 작업 실행 결과를 각각 구분한다.

## 공통 지식의 범위

배포본의 공통 본문에는 승인 범위·소유권, 독립 원문, 조건과 최종 소비처, 필요한 검증과 결과 재사용, 증거의 한계, 공식 복구, 미결 항목 보존, 역할 간 근거 전달을 둔다. 네 작업자 역할의 확인 책임도 같은 구간에 있다. 사용자 프로젝트의 요구사항이나 과거 개인 메모리 전체를 대신하는 지식 저장소가 아니다.

새 원칙은 현재 계약과 실제 실패·소비처를 대조해 일반화한다. 개인의 자동 실행 권한, 모델·횟수 설정, 제품 값, 과거의 DB 직접 수정·세션 초기화 처방은 공통 규칙으로 복원하지 않는다. 공통 본문과 개인 추가 자료의 내용이 겹친다고 개인 자료를 자동 삭제하거나 동기화하지 않는다.

## 유지되는 경계와 한계

설정 소스·훅·MCP·도구·읽기/쓰기 권한·승인·예산·소스 신선도 검사는 호스트가 계속 관리한다. 지침 전달을 줄이기 위해 사용자의 설정 소스나 원본 저장소 전체 접근을 열지 않는다.

Claude의 턴 도중 자동 압축이 발생하면 그 턴의 남은 구간에는 지침 요약이 남을 수 있다. 감지한 압축은 영수증을 지우며 다음 턴에 본문을 재전달한다. 이 방식은 압축 직후 같은 턴에 원문이 다시 주입됨을 보장하지 않는다.

## 전달 경계 재현

저장소에서 의존성을 설치한 뒤 다음 검사를 실행한다.

```sh
npm test -- tests/public-knowledge-delivery.test.ts tests/public-knowledge-briefing.test.ts
```

이 검사는 임시 사용자 홈과 빈 개인 지침·메모리 환경을 만들고 실제 어댑터·CLI를 실행한다. 공급자 실행 파일은 입력을 기록하고 정해진 결과를 반환하는 가짜 프로그램이므로 실제 모델·계정을 호출하지 않는다. 작업자 검사는 네 역할의 생성·재개 입력, 정책 변경 후 전달, 프로토콜·격리 제외와 독립 번들을 확인한다. 중재자 검사는 실제 CLI 출력에서 전체 정책과 버전을 확인한다. `CR_RECEIVED_EVIDENCE_DIR=/absolute/path`를 지정하면 작업자 검사의 수신 요약(본문 해시·등장 횟수·결과 형식)을 그 폴더에 보존할 수 있다. 실제 수신 원문은 임시 폴더에서 검사한 뒤 삭제한다.

실제 공급자 CLI의 샌드박스 동작, 중재자가 출력물을 자신의 세션에 붙여넣었는지, 모델의 해석·준수·토큰 절감률은 이 검사의 증명 범위가 아니다. 기존 어댑터 회귀 검사에서 실패·압축·재시작 영수증을 별도로 확인한다.
